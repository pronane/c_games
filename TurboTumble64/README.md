# TURBO TUMBLE 64

An original, N64-era style kart racer written in C99 + raylib. Everything except the optional
character sprites (models, textures, tracks, music, sound effects) is generated by code at start-up.
It contains no Nintendo assets, names, tracks or audio.

## Quick start (Windows 10/11)

1. Unzip anywhere (e.g. `C:\Games\TurboTumble64`).
2. Double-click **`build_release.bat`**.
   * It finds MSYS2 (`C:\msys64` and other usual places, or set `MSYS2_ROOT`), adds the UCRT64
     tools to PATH, installs `gcc` + `raylib` with pacman if they are missing, builds
     `TurboTumble64.exe` and launches it.
   * If MSYS2's raylib can't be linked it builds the bundled raylib 5.5 source in `deps/` instead.
   * If the build fails for any reason, it shows the error (full log in `build_log.txt`) and
     offers to launch the **prebuilt** game in `prebuilt\TurboTumble64.exe`.
3. Or just run `prebuilt\TurboTumble64.exe` straight away: it finds the `assets` folder
   one level up automatically (you can also copy the exe into this folder).

## Controls

| N64 button     | Gamepad (Xbox names)            | Keyboard                    |
|----------------|---------------------------------|-----------------------------|
| Stick          | Left stick / D-pad (small deadzone) | A/D or Left/Right       |
| A  accelerate  | **A**                           | W / Up / X                  |
| B  brake/reverse | **X** or **B**                | S / Down / Z                |
| R  hop / drift | **RB** (RT also works)          | Space / Shift / C           |
| Z  use item    | **LT** (LB also works)          | E / Ctrl / V                |
| Start  pause   | **Start / Menu**                | Esc / P                     |

* **Drift + mini-turbo:** hold R while steering into a bend - the kart hops and slides. Sparks
  behind the rear wheels turn **blue**, then **orange**; release R for a **TURBO!** (blue) or
  a longer, stronger **SUPER TURBO!** (orange, with flames and a camera punch). Steering
  *against* the drift opens it up, steering *into* it tightens it; wiggling charges faster. The
  bar under the speedometer shows the charge.
* **Items:** drive through a ? box and the HUD item box spins a slot-machine roulette that
  slows down and lands on your item. Press Z (LT) to use it.
* **F2** switches between ENHANCED (default) and the ORIGINAL N64 look, **F11** / Alt+Enter toggles fullscreen.
* Options -> **Controller setup** lets you remap Accelerate / Brake / Hop / Item / Pause:
  pick the action, press ENTER/A, then press the new button. Options shows the detected pad name.

### Gamepads (EasySMX and other USB pads)
The game loads two mapping files at start-up (pads can be plugged in or out at any time):
`assets/gamecontrollerdb.txt` (the community SDL GameController DB) and then
`assets/gamecontrollerdb_easysmx.txt` (extra EasySMX entries, generated by `tools/make_padmaps.py`).

| EasySMX mode (ESM-9101 / ESM-9013 / ESM-9110) | Shows up as | Covered by |
|---|---|---|
| **X-input** (default; hold HOME ~5 s to switch) | Xbox 360 pad `045e:028e`, or receiver `2f24:0091` / `2f24:00b7` / `2f24:0048` | Windows XInput; Linux xpad entries in both files |
| **D-input** (PC / DirectInput) | `20bc:9100`, `11c1:9101`, `20bc:9013`, `20bc:9110` | DInput layout (0=Y 1=B 2=A 3=X, 4/5 LB/RB, 6/7 LT/RT, 8 back, 9 start) |
| **Android** (Linux sometimes falls back to it) | SHANWAN "Android Gamepad" `0079:181c`, `2563:0526/0527` | Android layout (0=A 1=B 3=X 4=Y, 6/7 LB/RB, 10 back, 11 start) |

* **Unknown pads still work (generic fallback).** If a pad is not in either file, the game reads
  it as a raw joystick (winmm on Windows, `/dev/input/js*` on Linux) with the usual cheap-USB-pad
  layout: button 3 = accelerate, 4/2 = brake, 6/8 = hop, 7/5 = item, 10 = start; stick or D-pad
  steers. A toast says "USB controller detected (raw / DirectInput mode)".
* **Remap:** Options -> **Controller setup**. Pick the action, press ENTER/A, then press the new
  button or pull the trigger. A button can only do one thing (it moves away from its old action).
  Standard and raw pads have separate layouts, and both are saved in `turbotumble64.cfg`.
  Options -> **Pad mode** forces STANDARD or RAW if AUTO picks the wrong one.
* **EasySMX pad not responding?** Hold the **HOME / mode** button for about 5 seconds to switch it
  to **X-input** (the LEDs change), or set Pad mode to RAW and remap.
* Self-test (no pad needed): `TurboTumble64.exe --padcheck` checks that both mapping files load,
  that remapping follows the rules, and that the raw fallback reads binds.
* The mapping layouts match the community DB, but they were **not tested on a physical EasySMX**.

## Visual modes (Options -> Visual mode, or F2)
The game starts in **ENHANCED** on first launch. Your choice (F2 or Options -> Visual mode) is
saved in `turbotumble64.cfg` next to the exe; delete that file to reset all settings.
* **ENHANCED** (default, "N64 on steroids"): native resolution, 4x MSAA, full 3D racers with smooth
  bevelled bodies, spoked wheels and rim lighting, high-detail scenery meshes, about twice the
  draw distance, sun glow, and trilinear + 8x anisotropic textures.
* **ORIGINAL (N64 hi-res 640x480)**: 640x480 internal render (N64 hi-res) with a soft
  bilinear upscale and trilinear textures, so it looks soft and crisp rather than blocky. The racers
  are **pre-rendered sprites**, like the real thing: at startup every character is rendered from
  its high-detail 3D model into a sprite sheet (24 angles x 3 steering poses, supersampled, with a
  dark outline). On the track they're drawn as camera-facing billboards. Light distance haze only.
* **ORIGINAL RETRO (320x240)** - for purists: about 320x240 with a sharp integer point-filtered
  upscale (the v1-v3 look), still with sprite racers.
* All modes share the v4 art: procedurally generated textures, made in code at startup with no
  image files:
  - track surfaces: asphalt with grain and lane markings, raised red/white curbs, padded
    barriers with logos/arrows/hazard stripes, and a checkered start line;
  - ground: grass with clover and flowers, rippled sand, sparkling snow, wood/stone for Ghoulwood;
  - water: animated two-layer scrolling waves;
  - extras: rainbow tiles with live colour cycling on Starlight Spire, a painted 360-degree
    panorama per track (mountains, sea and islands, mesas and pyramids, pine peaks, haunted
    castles, nebula and ringed planet), clouds, billboards and turn chevrons.
* Dense scenery on every track:
  - plants: several tree types, palms, cacti, flowers, pines with snow;
  - farm and buildings: fences, houses, windmills, cows and hay bales, beach huts, boats, a
    lighthouse, pyramids, cabins, igloos, snowmen;
  - spooky: graves, pumpkins, ghosts and lanterns;
  - trackside: a grandstand with a crowd, pennants, a start gantry, and hot-air balloons.
  It's baked into spatial chunks (one draw per material per chunk) and frustum/distance culled.

## Modes
* **Grand Prix** - pick a cup (below), 3 laps per race, points 9-6-3-1 (classic style). After every
  race the cup standings show points gained and last-race places; after the last race comes the
  **trophy ceremony** (podium with the top 3 karts and a gold/silver/bronze cup).

  | Cup | Races |
  |---|---|
  | **Sprout Cup** (easy) | Grand Tumble Raceway, Clover Creek Farm, Shellby Shores, Coconut Cove |
  | **Blossom Cup** | Sunny Meadow Circuit, Dusty Dunes Rally, Frosty Peak Pass, Ghoulwood Manor |
  | **Thunder Cup** | Canopy River Parkway, Mudslide Megadome, Starlight Spire |
  | **Grand Tour** | all 11 courses back to back |
* **Time Trial** - solo with 3 peppers, best times saved per track. Your **best lap is saved as
  a ghost** (`ghost_track1.dat` ... next to the exe) and a translucent blue ghost kart races
  you on every later attempt (with the same racer or a different one). Delete the .dat files to
  reset ghosts.
* **VS** - 2-player split screen (keyboard halves or two pads).

## Tracks
All layouts are original; each has a **secret shortcut** (hinted on the track-select screen) and
the lap/checkpoint system accepts it while still blocking reverse-driving tricks.

| # | Track | Theme | Shortcut |
|---|-------|-------|----------|
| 1 | Sunny Meadow Circuit | raceway in the hills, windmills, ramp | gap in the fence across the meadow |
| 2 | Coconut Cove | beach, palms, huts, lighthouse, sea | sandy track behind the beach huts |
| 3 | Dusty Dunes Rally | desert with **bumpy moguls**, two jumps | gap after the first jump across the sand |
| 4 | Frosty Peak Pass | snowy mountain, slippery ice, moguls | snowy trail through the pines |
| 5 | Ghoulwood Manor | spooky haunted castle, boardwalk bumps | through the graveyard |
| 6 | Starlight Spire | long rainbow ribbon in the night sky | narrow star bridge |
| 7 | **Mudslide Megadome** | night indoor dirt supercross stadium | dark gap in the dirt bank at the top of the big U-turn |
| 8 | **Grand Tumble Raceway** | classic GP circuit: big sweeping right-hander, bridge, yellow-chevron tunnel, castle on the hill, grandstands, hot-air balloon | gap in the checkered wall across the infield grass |
| 9 | **Canopy River Parkway** | golden-hour jungle river: gorge jump over the river, riverside straight, paddle steamer, rope bridge, uphill cave, coconut monkeys | jungle trail inside the big left sweeper |
| 10 | **Shellby Shores** | turtle-beach style: tides that wash over the sand, scuttling crabs, a ramp hop over the lagoon, cave shortcut | little ramp into the cave in the cliff wall |
| 11 | **Clover Creek Farm** | cow-farm style: dusty lanes, mooing cows, moles that pop up underfoot, barns and fences | through the open gate and across the hay field |

**Mudslide Megadome** is a very wide dirt course sunk in a trench with sloped banks, under a black
sky with stadium light towers. It has:
* ribbed dirt with moguls that bounce karts into the air;
* light-blue walls painted with our dark-blue mascot face;
* red/white striped barriers on the raised overpass and ramps;
* stands packed with a crowd and camera flashes;
* a neon "BIG AIR" sign with a yellow arrow before the big jump;
* a blue jumbotron showing a live chase cam of the leader;
* a start truss with a black **TURBO TUMBLE 64** banner and chequered flags;
* rows of item boxes;
* its own music.
The course climbs onto a raised deck, jumps north over the lower east straight and crosses
itself. The checkpoints follow the deck, so the crossing can't be used to skip a lap.
`--stadium` runs a camera tour that takes 8 screenshots of it.

Shortcut trails are packed dirt (slower than tarmac): they only pay off if you **use a Pepper /
Disco boost or a mini-turbo** on the way in, or nail the line (the Starlight bridge is paved but
narrow). Moguls throw karts into the air; landing a real jump gives a tiny boost. Harder CPU
racers sometimes take the shortcuts too, especially when they hold a boost.

## Characters
Biscuit, Prof. Wobble, Nana Nitro, Captain Crumb, Zippy, Gloop, Big Tony, Frostina (built-in,
made from primitives), plus data-driven racers from `assets/characters/`:
* **v8 HD photo sprites:** Baby Éabha and Towelhead Qanna are now made from **their own photo /
  video pixels only** (no AI image generation on real people). Each is an 8-angle HD sprite sheet
  (512x640 per angle) sitting in the 3D kart; the game cross-fades between neighbouring angles as
  the camera moves, so turning looks smooth. Faces, clothes and colours are exactly as in the
  source photo/video.
  * **Towelhead Qanna**: front, 3/4, side and back frames are cut out from frames of her video
    (teal towel, oatmeal jumper). Medium class, teal spa kart with a rubber duck and the blinking
    comic **"I'M ANNOYING"** decal. Win card: drooping eyes, frown and anger mark, **"I didn't
    sleep last night"** (and a sleepy sway while she drives).
  * **Baby Éabha**: front and 3/4 views from her photo; the **back is invented** (mirrored
    silhouette, hair colour sampled from her head, jumper colour from her top) until a real back
    photo is added (`add_racer.py --back`). Light class, pastel kart with rattle and toy fruit,
    bubbly **"Milkies"** decal. Win card: smile line, blush and sparkles, **"Car!"** (and a happy
    bounce).
  * Win expressions are simple edits of the photo (tilt, eyelid/cheek shading, drawn marks).
* **Ruby Rocket**: an example made from a *text description* with `tools/add_racer.py --spec`
  (procedural cartoon drawing, see below).
* **Mango Mo**: the original example sprite racer (an illustration, not a photo).

### Add a racer from a photo or a description (`add_racer.bat`)
Windows: drag a photo onto **`add_racer.bat`** (it asks for a name; drop a second photo to use as
the back), or drag a `.txt` description onto it. First run installs MSYS2 Python, Pillow, numpy and
scipy through pacman (MSYS2 UCRT64 must be installed). Then start the game; new racers are found
automatically. From a shell:

```
python tools/add_racer.py --photo me.jpg --name "Speedy Me"
python tools/add_racer.py --photo front.jpg --back back.jpg --side side.jpg --name "Duo"
python tools/add_racer.py --spec tools/example/racer_spec_example.txt
python tools/add_racer.py --photo me.jpg --name Me --bg-box "0,450,295,1600" --fg-box "720,600,840,760"
```

* **Photo mode** cuts the person out automatically (face finder + GrabCut-style colour model,
  numpy/scipy only, no neural nets, works offline). If the background is close to the clothes,
  add `--bg-box` / `--fg-box` / `--face` hints (photo pixels) or a hints `.ini`. Then it builds the
  8 angles (warped and shaded views of the real photo; extra real `--side` / `--back` / `--view`
  photos replace the guessed ones), a portrait, a win sprite, a kart decal from `--kart-text`, and
  `character.ini`. Only the processed cut-outs are written; the original photo is never copied.
* **Spec mode** draws a new cartoon racer from a text description: ethnicity / skin tone,
  complexion, hair colour/style, eye colour and size, nose, ears, mouth, lips, freckles, glasses,
  height, weight, build, hands, feet, clothes. See `tools/example/racer_spec_example.txt` and
  `HOW_TO_ADD_A_RACER.txt`.
* The output (`sprite.png` sheet, `frame_w`/`frame_h`/`ground_y` keys) matches Sprite Forge's
  sprite-sheet layout, so sheets can be opened and edited there.

Honest limits: with one photo the side and back views are approximations (the face stays frontal
in 3/4 views, mirrored views mirror any text on clothes, an invented back is plain). Spec mode
draws a stylised cartoon, not a photo-real person.

### Add your own character (no code needed)
Every folder in `assets/characters/<name>/` with a `character.ini` becomes a racer:

```ini
name = Auntie Jo
tagline = Knits on the straights.
weight = medium          ; light / medium / heavy
speed = 3.5              ; 1..5
accel = 3.5
handling = 3.5
mass = 3.0               ; collisions
kart = 220,60,60         ; RGB
trim = 255,220,60
voice = 1.2              ; chirp pitch
sprite = sprite.png      ; HD PNG with transparency
angles = 16              ; 1 = single front billboard, 8 or 16 = sheet of pre-rendered angles
rows = 2                 ; frames laid out row by row (keeps big HD sheets under 4096 px wide)
size = 1.55              ; driver height in game units
portrait = portrait.png  ; square head shot for the character-select grid (optional)
kartstyle = spa          ; optional kart decoration: rattle / spa
; model = hero.glb       ; optional 3D model instead of a sprite
```

Names are UTF-8, so accents like "Éabha" display correctly. Sprite sheets are equal frames,
read row by row: frame 0 faces the camera, then the view rotates
clockwise; frame N/2 is the back view (like the original era's pre-rendered racers).

**Photo -> racer in one command** (needs Python 3 + Pillow + numpy; `pip install "rembg[cpu]"`
for neural background removal on real photos, otherwise a colour-key fallback is used):

```
python tools/make_character.py my_photo.jpg --name "Auntie Jo" --speed 4 --accel 3 --handling 3 --weight medium
python tools/make_character.py photo.jpg --name "Baby Éabha" --crop 500,760,1140,1430 --neck 0.49 ^
       --weight light --speed 2.5 --accel 5 --handling 4.5 --voice 1.75 --kart 255,165,205 --kartstyle rattle
python tools/make_character.py photo.jpg --name "Towelhead Qanna" --crop 380,400,1100,1330 --neck 0.57 ^
       --headback towel --voice 1.15 --kart 20,150,160 --trim 240,240,245 --kartstyle spa
python tools/make_character.py front.png --back back.png --name Duo      (real rear view)
python tools/make_character.py hero.png --name Hero --angles 1            (single billboard)
```
(Python options on Windows: install Python from python.org and run `pip install pillow`, or in the
MSYS2 UCRT64 shell `pacman -S mingw-w64-ucrt-x86_64-python-pillow` and run the same command there.
Start the game afterwards - the new racer appears on the character-select screen; run
`TurboTumble64.exe --gallery` to get a screenshot of every racer.)

It does the following:
* removes the background (rembg `isnet-general-use`, or `--model u2net_human_seg`);
* keeps the head and upper body (`--crop`, in photo pixels) and drops stray objects;
* makes a 512 px HD sprite with a slight sharpen and a thin dark outline, fading the bottom edge
  that the kart hides;
* builds the rear view: the back of the head is textured with the hair, towel or hat colour from
  the top of the head (`--headback`), the body with the clothing colour;
* lays out a 16-angle sheet and writes `assets/characters/<slug>/` (`sprite.png`,
  `portrait.png`, `preview.png`, `character.ini`).
Side and back views are made from one front photo, so they are approximations unless you pass
`--back` with a real rear photo. The source photo is never copied into the game folder.
`tools/example/mango_mo_photo.jpg` is the generated source image of Mango Mo.

Built-in characters live in `src/characters.c` (`CHARACTERS[]`) if you prefer code.

## Building by hand (MSYS2 UCRT64 shell)
```
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-raylib
gcc -std=c99 -O2 src/*.c -o TurboTumble64.exe -lraylib -lopengl32 -lgdi32 -lwinmm -mwindows
```

## Testing
`TurboTumble64.exe --autotest` drives every race with the CPU at the wheel (items, drifts,
shortcuts, moguls), checks laps / finish / checkpoint logic and writes `screenshots/autotest_log.txt`.
`--enhanced` runs it in ENHANCED mode, `--preview` takes a quick screenshot of each track,
`--gallery` renders every racer front/back plus close-ups of the 3D racers, `--only N`
runs just race N (7, the last one, also runs the cup ceremony, a checkpoint test and a Time Trial
ghost check on that track). `--quips` forces Éabha and then Qanna to win on Mudslide Megadome to
show the win screens. `--tour N` takes start / landmark / hazard shots of course N (8-11). `--stadium` is the stadium camera tour, and `--padcheck` is the controller
self-test.

Settings are saved in `turbotumble64.cfg` next to the exe.
