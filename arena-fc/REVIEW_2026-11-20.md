## 2. How this was verified (and the honest limits)

This sandbox could not install the toolchain: `release-assets.githubusercontent.com`, `dot.net`, `api.nuget.org` and `deb.debian.org` are all blocked, so neither Godot 4.7.2 nor the .NET 9 SDK could be fetched locally (`Tools/build.py --check` bootstraps from exactly those hosts). `gh release download` for Godot also fails with a TLS EOF.

So the run was done where the toolchain exists: **GitHub Actions is now the execution harness**, and it is automated in-repo, not ad-hoc:

* `dotnet-core` — engine-free guard → build solution → build authoritative server → core suite → match-core regressions → pad checks → sprite-forge checks → dead-core report.
* `godot-selftest` — **new job**: downloads Godot 4.7.2 (.NET), builds the assemblies and runs `godot --headless --path . -- --selftest`, i.e. the real game scene graph: skinned rig, GLB round trip, shaders, stadium, HUD, character editor and a simulated 3D match.
* `godot-gdscript` — browser-edition modules, replay, set-piece aim, pads, input/camera.
* `node-hub` — the shared Node WebSocket hub against the .NET-server protocol suites.

Compiler diagnostics and test tallies are now emitted as check annotations, so a red run is readable without log access.

## 3. Fixed on this branch

1. **CI red since 06 Nov — core polluted with Godot types.** `Scripts/Core/ClothSim.cs` used `Godot.Vector3` while living in the Godot-free core. Rewritten on `System.Numerics`, hardened (bad constraints, zero `dt`), covered by 8 new checks — it had zero callers and zero tests. CI now fails fast if `Scripts/Core` ever references Godot again.
2. **Cards were decorative.** A foul incremented `p.Cards` with no consequence: a player could be booked ten times and keep playing, and "Yellow card" commentary could fire with no card. Now: bookings are recorded, two yellows = red, denying a clear run on goal can be a straight red, a dismissed player leaves the pitch and takes no further part (no AI, no possession, no pass/switch target, no set-piece duty, never teleported back by a restart), and a side can never drop below two players.
3. **Tactics existed but were never used.** `TacticsPressMult` was declared, read once, and never written; the whole `Tactics` class had no callers. Mentality / pressing / width / tempo now reach the AI every tick, normalised so *Balanced* is bit-identical to the tuned baseline.
4. **Checkpoint & rollback lost most player state.** `ClonePlayer` copied ~18 of ~40 mutable fields (no dribbling, skill/jockey timers, `MustPlayBall`, tactics, cards). Capture/restore and resume silently diverged from the authoritative tick.
5. **`OverwriteState` dropped disciplinary and shootout state** — the mirror/predictor path used by `RestoreFrom` lost yellow/red tallies and penalty-shootout legs.
6. **`ApplyFull` copy-paste bug:** `p.Dribbling = d.Shielding; p.Sprinting = false;` — shielding became dribbling and sprint was force-cleared on every resume. The full-state payload also lacked dribble/sprint/sent-off/restart flags, cards and shootout legs.
7. **Stadium variety never worked.** `MatchView` built the stadium with the default index, so *every* fixture in the game — including all four "tournaments" — was played at Lions Den. It now uses the home club's ground and the requested quality preset.
8. **10 of 20 clubs pointed at stadiums that did not exist** (Harbor Ground, Pinnacle Dome, Frostbite Arena, …). Added; a core check now asserts `Clubs.All[i].Stadium == Clubs.Stadiums[i].Name`.
9. **A core test asserted "8 fictional clubs"** while the roster has 20 — a stale test that could no longer catch content drift. Replaced with league/stadium/kit invariants.
10. **In-engine tests were never run by CI.** 39 checks of real Godot nodes were manual-only; now automated (item above).
11. **Discipline was invisible.** The HUD never read `Cards`/`RedCards`; the scoreboard now shows yellow/red tallies once anyone is booked.
12. **The full-time screen showed three lines of prose** while the state tracked possession, shots, shots on target, passes, fouls, cards and corners. It now shows a real statistics block.

### P2 — polish / long tail

* No replay *editor* or photo mode (`ReplayEditor`, `PhotoMode` dead) even though `ReplaySystem` records events.
* No training drills or skill challenges with objectives/timers/leaderboards (`SkillGameResult` dead).
* No weather *gameplay* effect (rain/snow are visual only; no wet-pitch bounce, no wind on the ball).
* No goal-line technology / VAR review sequence despite `RefereeSystem.VarCheckGoal` existing.
* Injuries: `IsInjured`/`InjurySeverity` are declared and never written.

### 5.4 "Other major sports games" ideas that fit Arena FC

Chosen for fit with a 5v5/7v7/11v11 arcade-sim and cheap to build on what already exists:

1. **NBA 2K MyCareer-style player-lock career** — the sim already exposes per-player control and `PlayerProgress`; lock the camera to one player and grade every action (like 2K's teammate grade). *The `CareerMode` file is 80% of the model already.*
2. **Madden "Superstar" abilities / NHL X-Factor** — the `Badge` and `Evolution` types exist; make badges change simulation numbers (e.g. "Power Header" +x% aerial win).
3. **Rocket League-style ranked seasons with placement + rewards** — needs only MMR + persistence; the room/protocol layer is done.
4. **NBA 2K "Park"/Pro-Am social hub** — a shared lobby stadium where you walk your rig between courts; `ProClubs` + the character editor make this plausible.
5. **F1-style weekly "scenario" challenges** and **iRacing-style clean-race rating (safety rating)** — perfect fit for a deterministic sim: replay-verified, no server trust needed.
6. **MLB The Show "Moments" / FIFA Moments** — one-off historic scenarios with fixed seeds; trivial on top of `Replay` + `MatchOptions.Seed`.
7. **NHL/Madden instant replay + photo mode** — `ReplaySystem` already records events; the missing part is only a scrubbing UI.
8. **F1/NBA-style telemetry overlays** — the core already has positions at 60 Hz; xG (`ExpectedGoals`) and heat maps (`HeatMap`) are implemented and just need wiring.

## 6. Recommended roadmap

**P0 — make the promises true (1–2 weeks)**
1. Persistence layer (`user://arena_fc_save.json`): settings, career, UT club, tournament state. One `SaveGame` class in Core + Godot adapter.
2. Wire `TournamentSystem`: bracket screen, play fixture → advance → final, with `PlayerTeam` respected.
3. Post-match stats screen from `MatchAnalysis` + `HeatMap` + `ExpectedGoals` (all implemented).
4. Cards/reds on the scoreboard + dismissal banner.
5. Stoppage time: accumulate `AddedTime` from goals/cards/subs, play it out.

**P1 — depth parity (3–4 weeks)**
6. Substitutions: bench of 7, `Esc` → subs panel, `AIDepth` used only for the AI.
7. In-match tactics panel bound to the now-wired `Tactics` (mentality/press/width/tempo) + `MatchOptions` presets.
8. Ranked online: `Matchmaking` + MMR + `RankedSeason` on top of the existing v2 rooms.
9. Career mode UI over `CareerMode` (season fixtures, transfer offers, youth intake, morale).
10. UT: squad editor + transfer market + SBC execution.
11. Drill/skill-game framework (timed objective, score, retry) — unblocks `SkillGames`, `Training`, `PracticeArena`.

**P2 — differentiation (4–6 weeks)**
12. Player-lock career with per-action grading; badge/evolution effects in the sim.
13. Replay theatre + photo mode UI over `ReplaySystem`.
14. Crowd density/excitement wired to score, cards and match importance; commentary variation.
15. Accessibility pass: colour-blind palettes, subtitle sizing, assisted-control on by default for newcomers, remappable everything.
16. Localisation scaffolding (`tr()` + CSV) before the string count grows further.

**P3 — long tail**
17. Web/desktop simulation parity (share the core through structs/JSON, or accept web as "lite" and label it).
18. Weather affecting the ball and first touch; goal-line tech/VAR sequence.
19. Spectator + server browser; anti-cheat stats signatures.
20. Console/mobile store certification groundwork.
